## 1. 한 줄 정의와 문제

**친구끼리 약속에 가상 포인트를 거는 앱입니다.** 주최자가 [시작하기]를 누른 순간부터 서로의 위치가 보이고, 늦은 사람이 잃은 포인트는 제시간에 온 사람들이 나눠 갖습니다. 만난 뒤에는 원래 이 앱이 하던 모임 정산으로 그대로 이어집니다.

문제는 4~6명이 저녁에 만나기로 한 흔한 자리에서 생깁니다.

- 약속 시각이 되면 단톡방에 "어디야?"가 반복됩니다. 온 사람은 몇 분을 더 기다려야 하는지 모른 채 가게 앞에 서 있습니다.
- 위치 공유는 약속과 분리돼 있습니다. 각자 켜고 각자 끄는 일이라, 필요한 30분 동안만 켜기가 번거롭고 한 명이 안 켜면 소용이 없습니다.
- 늦는 데 아무 대가가 없습니다. 매번 같은 사람이 늦고, 나머지는 말을 꺼내기 불편해 넘어갑니다.

이 앱은 원래 정산 앱이었고(`215e16e`, 2026-07-07), 2026-09-01(`fb2f079`)에 "모임이 곧 약속이 된다"며 약속 시각·장소를 붙였습니다. 약속 내기는 그 앞단에 **판정**을 붙인 것입니다.

## 2. 목표와 비목표

**목표**

1. 약속 시각과 장소를 기준으로 **자동으로** 도착을 판정합니다(사람이 "왔다"고 주장하지 않아도 됩니다).
2. 늦음에 작고 되돌릴 수 있는 대가를 붙입니다. 벌이 아니라 놀이로 읽히는 크기여야 합니다.
3. 만난 뒤 정산 화면까지 한 흐름으로 잇습니다.

**비목표 — 이번 범위에서 하지 않기로 한 것과 이유**

## 3. 사용자와 시나리오

**흐름 A — 주최자(민수)가 금요일 저녁 약속을 잡습니다**

1. 홈 → [약속 잡기]. 제목·날짜·시간·장소 핀·**초대할 친구 이름 명단**·걸 포인트(프리셋)를 정합니다.
2. 초대 문구를 단톡방에 공유합니다. 링크는 `https://…/?c=<8자 코드>`이고 같은 문구에 평문 코드도 함께 들어갑니다(앱을 이미 깐 사람은 딥링크 `nbbang://j/<코드>`로도 열립니다).
3. 친구들이 들어와 **명단에서 자기 이름을 고르고** 포인트를 겁니다. 이때는 아무도 서로의 위치를 못 봅니다.
4. 약속 시각 전에 민수가 [시작하기]를 한 번 누릅니다. **그 순간부터** 참여자끼리 위치가 보입니다.
5. 가는 동안 앱을 켜 두면 지도에 서로가 보이고, 약속 장소 반경 안에 들어오면 서버가 도착으로 찍습니다.
6. 마감이 지나면 결과 화면이 뜨고, [정산 시작]을 누르면 참여자 닉네임이 그대로 모임 정산 화면으로 넘어갑니다.

**흐름 B — 초대 코드로 들어온 친구(현우)**

링크를 누르면 조건 카드(시각·핀 지도·정책 전문·예시 "10분 늦으면 −20P")를 먼저 봅니다. 명단에서 자기 이름을 고르고 동의 2개(위치 제공 / 만 14세 이상)를 체크한 뒤 [100P 걸고 참여]를 누릅니다. 시작 전에는 언제든 [나가기]로 전액을 돌려받습니다.

## 5. 규칙·판정 설계 — 코드 기준 실제 값

### 정책과 범위

`stake` 0~300P, `radiusM` 30~1000m(기본 100), `unitMinutes` 1~60분, `penaltyPerUnit` 0~300P, `graceMinutes` 0~30분. 여기에 CHECK 제약 하나가 더 있습니다. **전액을 잃기까지 180분 이내**여야 합니다("179분 지각 −179P, 181분 지각 전액" 같은 절벽 정책을 DB가 거부합니다).

프리셋 3종은 순한맛 100P·10분마다 −10P(90분 넘게 늦으면 전액), 보통 100P·5분마다 −10P(45분), 매운맛 300P·1분마다 −10P(29분)입니다.[^1]

### 지각과 차감

- 지각 단위 = `ceil((도착 − 약속시각 − 봐주는시간) / 단위분)`. **1ms만 넘겨도 1단위**입니다. 경계(정확히 약속 시각)는 정시로 봅니다.
- 잃는 포인트 = `min(stake, 단위수 × 단위당차감)`. 안 온 사람은 전액입니다.
- 분배 = `floor(모인포인트 / 제시간도착자수)`씩, 나머지 r포인트는 **일찍 온 순서로 1P씩** r명에게 갑니다. 동률이면 참가자 배열 순서라 결과가 항상 같습니다.
- 불변식: `sum(net) === 0`, 모든 값은 정수, `forfeited ∈ [0, stake]`.

### 애매한 입력을 닫는 방식

이 앱에서 가장 신경 쓴 부분입니다.

| 애매한 입력 | 처리 |
| --- | --- |
| 제시간에 온 사람이 0명인데 잃은 포인트는 있음 | **무효 + 전원 환불**(`noWinner`) — 받을 사람이 없음 |
| 약속 시각이 쓰레기 값(NaN·Infinity·Date 범위 ±8.64e15 밖) | **무효 + 전원 환불**(`invalidDeadline`) — 판정 근거가 없음. 조용히 전원 노쇼가 되지 않게 사유를 남김 |
| 주최자가 끝내 [시작하기]를 안 누름 | 약속 시각에 **자동 무효 + 전원 환불**(`notStarted`) |
| GPS 정확도가 100m 초과이거나 음수(iOS는 무효 측정에 −1) | 도착 **불인정**. 다만 `거리 − min(정확도, 300m) ≤ 반경`이면 '근처에 온 첫 시각'만 기록(친구가 [같이 있어요]로 보증할 때 그 시각을 씀) |
| 정확도 1000m 초과 / 안드로이드 모의 위치 | 좌표를 **저장하지 않음** |
| 좌표가 유효하지 않음 | 거리 계산이 `Infinity`를 돌려주므로 어떤 반경 비교도 통과하지 못함(NaN은 비교식에서 조용히 false가 되어 쓰지 않음) |

### 시각 경계

- 체크인·위치 공개 마감(`closeMs`) = 전액 몰수 시각 + **30분**, 상한 약속 시각 + **180분**, 전액 몰수 시각이 없으면 약속 시각 + **60분**.
- 위치 공개 창 = `[시작하기] 누른 서버 시각 ~ closeMs`. 도착하면 그 사람 좌표는 **즉시 삭제**, 3분 지나면 친구 응답에서 빠지고, 10분 지나면 서버에서 지워집니다.
- 정산 시점 = `마감 + 15초` 또는 `전원 도착 ∧ 약속 시각 이후` 또는 `미시작 ∧ 약속 시각 이후`. 15초는 Supabase의 문장 타임아웃 8초보다 길게 둬, 마감 직전에 시작된 체크인이 정산보다 반드시 먼저 끝나게 한 여유입니다.

| 참여 통제 = **초대 명단**(이름 고르기) | 주최자 수락제(요청 → 승인) | 수락제는 주최자가 앱을 켜고 있어야 하고, 당일 번개 약속에서 한 명씩 수락해야 했음 | 차단 목록(`lb_bans`)은 남겨 내보내기에서 재사용 |
| 판정은 **서버 시계·서버 거리** | 폰이 계산해 보고 | 폰 시계는 바꿀 수 있고 기기마다 다름 | 도착 판정 RPC에 시각 인자를 두지 않아, 클라이언트가 도착 시각을 주장할 길이 없음 |
| 같은 규칙을 **TypeScript와 SQL 두 벌**로 | 서버 함수에서 TS를 재사용 | 앱은 미리보기·가짜 서버 때문에 판정이 필요하고, 서버는 권위가 필요함 | 어긋남은 `test:parity`가 잡음. 권위는 SQL이라고 주석에 못 박음 |
| **서버 1개 + 5·10초 폴링** | Realtime 구독·Edge Function·pg_cron | 상시 운영 부품을 늘리지 않기 위해. 아무도 앱을 안 열면 정산이 늦어질 뿐 결과는 같음 | 폴링이 한 곳(`useLive`)에 모여 있어 Realtime을 "변경 신호 → 즉시 폴링"으로만 얹을 수 있음 |
| **가짜 서버로 전 화면을 먼저**(1단계) | 서버부터 붙이고 화면 | 이 순서 덕에 Supabase 프로젝트 없이 2단계까지 끝냄 | 모드 3단계(`off`/`fake`/`live`). 기본 `off`는 기존 정산 앱과 같고, `fake`는 개발 번들과 TestFlight `beta` 채널에서만 켜지며 production 릴리스 번들에서는 무조건 `off` |
| 포인트 이동은 **원장(ledger, 지울 수 없는 거래 기록) 한 곳** | 잔액만 갱신 | 잔액이 틀어졌을 때 원인을 되짚을 수 있어야 함 | UPDATE·DELETE를 트리거가 거부하고, 원장 불변식 6개를 포함해 감사 함수 `private.lb_audit()`의 불변식 12개가 전부 0행이어야 정상 |

## 7. 제가 정한 것과 AI에 맡긴 것

**제가 정한 것**은 제품 규칙입니다. 설계서에 확정 표시와 날짜로 적어 뒀고, 그 표가 코드보다 위에 있습니다.

- 최종 흐름(초대 → 수락 → **[시작하기]** → 위치 공개 → 판정 → 정산)과 규칙 9개(§0-1, 2026-09-18).
- 공정성 규칙 R1~R4의 숫자(180분·500m·5분)와 "시작 전부터 있던 사람은 못 내보낸다"는 방향(2026-09-19, 5절).
- 하지 않을 것: 백그라운드 위치, 현금 가치, 원격 푸시, 전역 랭킹.
- 반려도 제가 했습니다. 기본 반경을 150m로 올리자는 비평은 100m 유지로 기각하고 "첫 현장 테스트에서 오판이 나오면 올린다"로 미뤘습니다.

**AI에게 맡긴 것**은 설계서 초안(정합성·MVP·UX 세 관점으로 각각 쓴 뒤 통합), 적대적 비평 30건을 만들어 하나씩 반영/기각 판정한 표, SQL 마이그레이션, TypeScript 구현, 테스트, 화면입니다.

**AI 결과물을 어떻게 검증했는가** — "테스트가 통과한다"만으로는 못 믿기 때문에 각도를 겹쳤습니다.

1. **판정 로직을 순수 함수로 강제했습니다.** `lateBet.ts`·`geo.ts`·`lateEditRules.ts`는 I/O도 `Date.now()`도 기기 시간대도 읽지 않습니다(시각은 전부 인자). 덕분에 경계값을 테스트로 고정할 수 있습니다.
2. **같은 규칙을 두 벌 만들고 대조했습니다.** `test:parity`가 무작위 7,000건으로 TypeScript와 SQL의 답을 비교합니다.
3. **가짜 서버와 진짜 SQL을 나란히 돌렸습니다.** `test:conformance`가 같은 시나리오를 양쪽에 걸음마다 넣고 응답을 대조합니다. **처음 돌렸을 때 차이 8건이 나왔고**(13자 이름을 가짜 서버만 받아들임, 핀을 옮겨도 '근처에 온 시각'이 안 지워짐 등) 전부 고친 뒤 0이 됐습니다. 양쪽 단위 테스트만으로는 못 찾았을 종류입니다.
4. **적대적 리뷰가 찾은 구멍을 실제로 막았습니다.** R4 검증 중 "마감이 지나 결과는 정해졌는데 정산이 아직 안 돈 최대 15초 사이에 주최자가 당첨자를 내보내 자기 몫을 키울 수 있다"는 경로가 나왔습니다. `now > close_at`이면 `LB_KICK_CLOSED`로 막고 SQL 단언 3개·테스트 1개·대조 1걸음을 더했습니다. 규칙 엔진 첫 커밋에서도 "유한하지만 말이 안 되는 거대한 시각(1e308)에서 지각 분이 `Infinity`로 새던 것"을 잡았습니다(`12fc2c3`).
5. **커밋 근거**: main의 커밋 44개 **전부**에 `Co-Authored-By: Claude` 표기가 있습니다(`git log -i --grep="Co-Authored-By: Claude"`). 약속 내기 기능 커밋에는 그 시점의 테스트 수를 함께 적어 뒀습니다(214 → 405 → 587 → 668 → 708).

정직하게 적으면 **코드의 대부분은 AI가 썼습니다.** 제가 한 일은 규칙을 정하고, 범위를 자르고, "이 숫자는 어디서 나왔냐"를 묻고, 검증이 통과할 때까지 결과를 받지 않은 것입니다.

## 8. 리스크와 남은 일

- **실기기 확인은 아직입니다.** 지도·GPS·로컬 알림이 들어간 2단계는 코드 경로와 웹 프리뷰까지만 봤습니다(이 머신에 Xcode가 없습니다). **다음 한 수**: 체크리스트가 `docs/late-bet-p0-handoff.md`에 있고, Xcode가 있는 환경에서 TestFlight `beta` 빌드로 반나절이면 돕니다.
- **실제 Supabase 프로젝트가 아직 없습니다.** 서버 규칙은 로컬 PostgreSQL 16으로만 검증했습니다. **다음 한 수**: 프로젝트를 만들어 마이그레이션을 올리고 같은 `test:sql`·`test:conformance`를 원격에서 한 번 더 돌립니다. 초대 랜딩 페이지도 아직 배포하지 않아 링크 주소(`INVITE_PAGE_URL`)가 미확정입니다.
- **GPS 조작을 완전히 막을 수 없습니다.** 모의 위치 플래그와 정확도 캡은 둘 다 클라이언트 보고값이라 작정하면 우회됩니다. 이건 구조적 한계이고, 그래서 포인트에 돈 가치를 붙이지 않았습니다. **다음 한 수**: 친구 보증(`lb_vouch`)처럼 사람이 개입하는 경로를 넓힙니다.
- **동시성과 규칙 우회 검증이 남았습니다.** 같은 사람 체크인 10건 + 조회 5건 병렬, 체크인을 일부러 세워 두고 정산이 먼저 지나가는 재현이 남았고, R1~R4에 대한 적대적 우회 리뷰도 제가 중단시켜(`0b7ca37`) 아직 돌리지 않았습니다.
- **법 검토**: 남에게 위치를 보여 주는 서비스라 공개 출시 전 위치기반서비스 신고 여부를 확인해야 합니다. 동의 기록·만 14세 확인·제공 사실 로그는 소급 생성이 불가능해 첫 마이그레이션부터 넣었습니다. 이 문서는 법률 자문이 아닙니다.
