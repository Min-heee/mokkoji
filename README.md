# 정산야호

약속 지키기 앱. 친구들과 약속을 잡고 각자 가상 포인트를 건다. 주최자가 [시작하기]를 누르면 그때부터 서로의 위치가 보이고, 제시간에 약속 장소 반경 안에 들어온 사람은 건 포인트를 돌려받는다. 늦은 사람은 늦은 만큼 깎이고, 깎인 포인트는 제시간에 온 사람들이 나눠 갖는다. 만난 뒤에는 모임 정산(차수별 · 항목별 · 다중 통화) 화면으로 그대로 이어진다.

> 개발 중. 약속 내기는 아직 서버에 연결되지 않았고, 지금 `main`에서는 메모리 안의 가짜 서버로 전 화면이 돈다. 스토어 출시 전이다.

## 사용자 흐름

1. **약속 잡기** — 주최자가 시간 · 장소 · 도착 인정 반경 · 걸 포인트와 지각 차감 규칙을 정하고, 초대할 친구 이름을 명단에 적는다. 초대 링크(`nbbang://j/<코드>`)나 코드를 공유한다.
2. **수락** — 친구는 링크나 코드로 들어와 명단에서 자기 이름을 고르고 포인트를 건다. 시작 전에는 나가기(환불) · 내보내기 · 명단 편집 · 시간/장소/조건 변경이 모두 된다. 이때는 아무도 위치를 못 본다.
3. **시작하기** — 주최자가 약속 시각 전에 [시작하기]를 한 번 누르면 그 순간부터 참여자끼리 위치가 보인다. 시작 뒤에는 시간을 뒤로 미루거나 장소만 바꿀 수 있다. 시작하지 않은 약속은 약속 시각에 자동으로 무효가 되고 전원 환불된다.
4. **도착 · 지각 판정** — 앱을 켜 둔 동안만 위치를 보낸다. 도착 · 지각 판정과 포인트 계산은 서버 시계 기준이고, 폰 시계는 화면 카운트다운에만 쓴다.
5. **정산** — 결과 화면에서 [정산 시작]을 누르면 참여자 닉네임이 모임 정산으로 넘어간다.

포인트는 가상 포인트이고 돈으로 바꿀 수 없다.

## 정산 기능

약속 내기 이전부터 있던 모임 정산 기능. 로컬(AsyncStorage)에 저장하고 로그인 없이 쓴다.

- **차수** — 1차 카페 → 2차 밥 → 3차 술처럼 차수마다 결제자와 참가자가 다를 수 있다.
- **정산 방식** — 차수별로 `균등 정산`(총액만 입력) 또는 `항목별`(메뉴마다 단가 · 수량 · 먹은 사람 지정).
- **통화** — 차수별 결제 통화 선택. 현금은 환율 입력(실시간 환율 조회, 오프라인이면 캐시), 카드는 실제 청구된 원화 금액 입력.
- **열외** — 생일자 등 돈 안 내는 사람의 몫은 나머지가 균등 부담.
- **송금 정리** — 사람별 `결제액 − 부담액`을 계산해 송금을 인원 − 1번 이하로 정리하고, 송금액은 반올림 단위의 배수로 맞춘다.
- **내기 게임 10종** — 룰렛 · 사다리타기 · 제비뽑기 등. 결과가 정산에 반영된다.
- **친구 목록과 친구별 돈 장부** — 모임 참가자를 친구 목록에서 고르고, 보낼 돈 · 받을 돈을 기록한다.

## 단계

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| P0 | 초대 → 수락 → [시작하기] → 위치 공개 → 도착 · 지각 판정 → 결과 → 정산 전 화면, 가짜 서버(봇 친구 · 시간 빨리 감기) | `main` 병합 (2026-09-18) |
| P1 | 실제 지도(react-native-maps), 장소 고르기, 앱을 켜 둔 동안의 GPS 도착 판정, 로컬 알림, 햅틱. 앱 버전 0.4.0 | 개발 브랜치 `feat/late-bet-p1`, 실기기 확인 뒤 병합 예정 |
| P2 | Supabase 연동 | 진행 중 |

서버는 Supabase(PostgreSQL) 하나만 쓴다. 별도 서버 프로그램 없이 앱이 DB 함수(RPC)를 부르고 주기적으로 새로 묻는다. 스키마와 함수는 `supabase/migrations/`, 시나리오 테스트는 `supabase/tests/`에 있다.

## 약속 내기 모드

`EXPO_PUBLIC_LATEBET_MODE` 값으로 약속 내기를 켜고 끈다(`.env.example` 참고).

| 값 | 동작 |
| --- | --- |
| `off` (기본) | 약속 내기 UI가 보이지 않는다. 모임 정산 앱으로만 동작 |
| `fake` | 메모리 가짜 서버. 개발 번들(`__DEV__`)과 웹 프리뷰에서만 켜지고 릴리스 번들에서는 `off` |
| `live` | Supabase. 웹이 아니고 `EXPO_PUBLIC_SUPABASE_URL` · `EXPO_PUBLIC_SUPABASE_KEY`가 모두 있을 때만 켜진다 |

## 스택

Expo SDK 54 · expo-router 6 · React Native 0.81 · React 19.1 · TypeScript strict · AsyncStorage · expo-updates(OTA) · Supabase(PostgreSQL, plpgsql RPC) · 테스트는 `node:test` + `tsx`

## 구조

```
app/
  index.tsx                  # 홈: 약속 · 정산 모임 목록
  late/                      # 약속 내기: 약속 잡기, 장소, 포인트, 약속 화면(대기실 → 진행 → 결과)
  j/                         # 초대 코드 입력, 초대 링크로 참여
  session/                   # 모임 정산: 새 모임, 차수 편집, 내기 게임, 정산 결과
  friends/                   # 친구 목록, 친구별 돈 장부
src/
  domain/                    # 순수 로직(UI 독립, 테스트 대상): 정산, 통화, 내기, 지각 판정, 위치 공개 창, 초대 코드
  lateBet/                   # 약속 내기 클라이언트: API 계약, 가짜 서버, 모드 규칙, 화면 조각
  services/ state/ storage/ ui/
supabase/                    # 마이그레이션, SQL 시나리오 테스트
docs/                        # 약속 내기 설계서, 작업 인수인계 메모
```

## 명령어

```bash
npm start            # Expo dev server
npm run web          # 웹 프리뷰
npm test             # 단위 테스트 (정산 엔진 + 약속 내기 도메인 · 클라이언트)
npm run typecheck    # tsc --noEmit
npm run test:sql     # 로컬 PostgreSQL 16에 마이그레이션을 올리고 SQL 시나리오 테스트 실행
npm run test:parity  # TypeScript 지각 판정과 SQL 판정의 결과 일치 확인
npm run ota          # production OTA 발행 (EAS 환경에 Supabase URL이 없으면 거부)
npm run ait:build    # 앱인토스(토스 미니앱)용 웹 빌드 (실험, 현재 계획 없음)
```

## AI로 만든 방식

Claude Code와 함께 만들었고, 모든 커밋에 `Co-Authored-By: Claude` 표기가 있다. 무엇을 만들지와 규칙(언제 위치를 공개할지, 시작하지 않은 약속을 어떻게 처리할지 등)은 내가 정하고 설계서(`docs/appointment-bet-design.md`)의 '내 확정' 절에 적는다. 설계서는 적대적 비평 30건을 하나씩 판정해 반영한 뒤 구현에 들어갔고, 지각 판정은 TypeScript 순수 함수와 SQL 두 벌로 만들어 같은 입력에 같은 답을 내는지 테스트로 맞춘다.
